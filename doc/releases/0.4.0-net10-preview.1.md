DXSharp brings Direct3D 12, GPU compute, DXC, and DirectML to C# 14 and .NET 10. This first public .NET 10 preview gives graphics programmers, engine developers, tool builders, and coding agents a tested foundation for native Windows graphics and compute applications.

Aaron Carter began DXSharp with the idiomatic feel of Managed DirectX, XNA, SlimDX, and SharpDX in mind. The .NET 10 work carries that intent forward with source-generated COM calls, deterministic ownership, and executable graphics and numerical qualification.

The current supported preview target is Windows x64, with the Windows SDK target set to 10.0.26100.0. Xbox/GDK, ARM64, and additional UI hosts are future qualification work. API coverage is growing, and preview APIs can change.

## Packages and entry points

| Package | Use |
| --- | --- |
| `DXSharp.Core` | D3D12 and DXGI resources, queues, pipelines, swap chains, DXC compilation, and a bounded DXR API |
| `DXSharp.Framework.Desktop` | WinForms hosting, buffered frames, resize, presentation, and queue retirement before window destruction |
| `DXSharp.DirectML` | DirectML Add and GEMM with optional fused ReLU, tensor binding, and execution |

The version for all three is `0.4.0-net10-preview.1`. The release assets contain these packages, their portable symbols, and a manifest binding file hashes to the source commit. The workflow reports NuGet.org publication independently from asset publication.

After the NuGet publish job succeeds, install the package needed by your application.

```powershell
dotnet add package DXSharp.Framework.Desktop --version 0.4.0-net10-preview.1
dotnet add package DXSharp.DirectML --version 0.4.0-net10-preview.1
```

Both depend on Core. A renderer or compute application can reference Core directly. Use a Windows x64 .NET 10 project targeting `net10.0-windows10.0.26100.0`. Native Agility, DXC, and DirectML runtime assets flow through the packages and their MSBuild targets.

For source exploration, check out this release tag and run the bounded samples.

```powershell
git clone --branch v0.4.0-net10-preview.1 https://github.com/atcarter714/DXSharp.git
cd DXSharp
dotnet run --project samples/ModernTriangle -c Debug -- --warp --buffered --frames=8
dotnet run --project samples/ModernCompute -c Debug -- --warp --directml --gemm --latest-shader-model
dotnet run --project samples/NBodyGravity -c Release -- --bodies=1024
dotnet run --project samples/DxrHelloWorld -c Debug
```

The DXR sample performs image validation on a capable adapter and writes a PPM image. Its capability check reports unsupported adapters separately. Debug-layer validation requires Windows Graphics Tools.

## Technical assessment

The modern binding path uses CsWin32 declarations and .NET's generated COM dispatch. Native references are owned explicitly. Command recording retains resources, and queue retirement releases submission references after fence completion. Applications retain control of command recording, memory placement, resource states, and synchronization.

The release pins Agility SDK 1.620.1, DXC 1.9.2609.5, and DirectML 1.15.4. Compiler support and adapter support are checked separately. The shader qualification compiles Shader Model 6.9 and dispatches the highest profile supported by the qualified compiler and selected device. Shader Model 6.10 is a separate developer-preview track.

GitHub qualification covers Windows Debug and Release builds, baseline tests, clean package consumption, WARP rendering and numerical checks, and native COM fixtures under JIT and NativeAOT on Windows and Linux x64. Linux exercises the portable COM fixture. The graphics samples run on Windows. The native fixture checks 2,288 conditions and observes destruction of 2,004 native objects with zero live objects.

The author also verified DXC compute readback and DXR image output on an NVIDIA GeForce RTX 3080 Ti. The DXR run compiled a 5,636-byte shader library and validated 12,004 hit pixels and 36,462 miss pixels. The N-body numerical qualification compares GPU output against a seeded CPU reference. WARP also exercises both final frame slots during bounded N-body window shutdown.

This evidence qualifies specific paths. Broader vendor coverage, hardware soak tests, complete D3D12 coverage, device-loss recovery, and more DirectML operators remain release goals. NativeAOT qualification covers the native fixture and the compute/ML sample. The WinForms desktop host has its own JIT qualification. Modern authored public and protected APIs have a compiler-enforced XML documentation gate. The original RCW compatibility APIs have a separate documentation and migration backlog.

The DXR run can emit the Agility advisory recommending `ID3D12Device16.CheckFeatureSupport1`. Version-aware feature querying is an outstanding binding update. Efficiency and scale are design goals. Comparative throughput and memory claims require controlled benchmarks.
