# DXSharp 0.4.0-preview.3

This preview adds .NET 10 and .NET 11 package assets, updates the native D3D12 declarations to the pinned retail Agility baseline, and rejects invalid command allocator/list recording reuse before issuing native calls.

## Runtime and packages

The five modern packages are DXSharp.Native, DXSharp.Core, DXSharp.Assets, DXSharp.DirectML, and DXSharp.Framework.Desktop. Graphics packages target net10.0-windows10.0.26100.0 and net11.0-windows10.0.26100.0; Assets targets net10.0 and net11.0. Windows graphics qualification remains x64.

Samples default to .NET 10. Select .NET 11 with `-p:DXSharpRuntimeMajor=11`. Building the checkout uses SDK 11.0.100; applications consuming the .NET 10 assets can continue targeting .NET 10.

The dependency pins are Agility 1.620.2, DXC 1.9.2609.5, optional DirectML 1.15.4, Win32Metadata 71.0.45-preview, and CsWin32 0.3.371. Generator dependencies remain private build dependencies.

## Native surface and compatibility

The selected D3D12 reference accounts for 752/752 top-level type names and 4,882/4,882 measured member names, resolving the preceding audit's 107 missing D3D12 names. Coverage now compares interface identifiers and fails missing required references or overlapping metadata providers.

This is a preview API compatibility change: older shared shader-cache declarations and associated generated helpers, and SC_HANDLE helpers, are absent from the selected metadata projection. Consumers using them must review the [coverage and migration notes](https://github.com/atcarter714/DXSharp/blob/main/doc/API-Coverage.md). This does not establish that the corresponding native Windows APIs were removed.

Name and IID coverage are not complete ABI verification. Comprehensive signature, inheritance/vtable, and layout verification remains open.

## Recording ownership

Command allocators reserve one active recording list. Creating a second recording list against the same allocator, resetting an allocator during recording, and resetting an open list now fail deterministically in managed code. Failed native create/reset calls roll back the reservation. Closing or disposing a recording releases it; pending GPU submissions still prevent unsafe reuse.

A disposed command list releases its native list before its retained recording dependencies. Applications remain responsible for synchronization, resource states, and declaring dependencies used by native recording callbacks.

## Qualification and scope

The merged baseline passed Windows Debug/Release and .NET 10/11 native COM JIT/NativeAOT qualification on Windows and Linux. Native fixtures passed 2,298 checks with zero live objects. Both runtime paths passed package-consumer builds, all 12 package-based sample builds, and Windows WARP sample/lifecycle checks.

The release workflow requalifies the exact release commit and verifies the staged packages before publication. Linux evidence covers the portable COM fixture, not a Linux DirectX renderer. Additional hardware/vendor coverage and production resilience remain open.

This release does not add general descriptor/upload allocation, DirectStorage, current GameInput qualification, or Media Foundation/D3D12 video integration. No proprietary Noesis dependency is introduced. See the [support matrix](https://github.com/atcarter714/DXSharp/blob/main/doc/Support-Matrix.md) and [parity roadmap](https://github.com/atcarter714/DXSharp/blob/main/doc/Competitive-Parity-Roadmap.md).

NativeAOT qualification writes RID/runtime-specific lock files under artifacts/aot-locks, preserving committed JIT locks when both runtimes are qualified in one workspace.
